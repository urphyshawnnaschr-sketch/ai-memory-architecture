# 五条核心原则

[← 返回目录](../README.md) | [上一章](01-why.md)

> 这些原则不是设计出来的，是踩坑踩出来的。每一条背后都是真实的教训。

---

## 原则一：单一进度源 (Single Source of Progress)

### 规则

> 每件事的进度，**只在一个地方记录**。其他需要提到进度的地方，只放一个指针（"详见 XXX"）。

### 为什么

我们曾经犯过这个错：同一个项目的进度，记在了 AI 记忆里一份、工作日志里一份、会话书签里一份。三份进度，三个版本，没有一个是最新的。

最可怕的是：**你不知道自己在用过期的进度**。AI 一本正经地基于旧进度给你建议，你还觉得它说得对。

### 怎么做

```
✅ 正确做法：
工作日志：  "项目A：第三步完成，第四步进行中"
AI 记忆：   "项目A进度 → 详见工作日志"
会话书签：  "项目A进度 → 详见工作日志"

❌ 错误做法：
工作日志：  "项目A：第三步完成"
AI 记忆：   "项目A：第二步完成"（忘了更新）
会话书签：  "项目A：做了第一步和第二步"（更早的版本）
```

### 一句话

**多份副本 = 多个谎言。只有唯一的那一份是真话。**

## 原则二：核心记忆极简 (Minimal Core Memory)

### 规则

> 塞进 AI 常驻记忆的东西越少越好。**如果一条信息只在特定场景下有用，它就不该常驻。**

### 为什么

AI 的常驻记忆（Custom Instructions / System Prompt / Memory）每次对话都会加载。如果你塞了 5000 字进去，AI 每次都要读完这 5000 字才开始回答你。

这带来两个问题：
1. **容量浪费** — 今天聊的是写作，但 AI 也把你的编程偏好加载进来了
2. **注意力稀释** — 信息太多，AI 反而抓不住重点

### 怎么做

核心记忆里只放三类东西：

```
1. 你是谁（名字、角色、基本偏好）
2. 通用规则（永远适用的行为准则）
3. 路由信息（"聊 XX 话题时，去加载 YY 文件"）

其他所有东西 → 外挂记忆
```

### 一句话

**核心记忆是身份证，不是行李箱。**

## 原则三：暗号触发 (Codename Trigger)

### 规则

> 用一个暗号把 AI 的注意力导向对应的记忆域。不相关的记忆，不加载。

### 为什么

你同时在做三件事：写小说、管项目、运营社群。这三件事的背景信息加起来可能有几万字。全部塞给 AI？它会疯的。

更好的办法：**告诉 AI 一个暗号，它就知道该去读哪一块记忆。** 就像谍战片里的接头暗号——你说一个词，对方就知道你是谁、要什么。

### 怎么做

在 AI 的核心记忆里，放一张暗号表：

```
暗号表：
- "聊写作" → 加载 writing/worklog.md
- "聊项目" → 加载 project/worklog.md
- "社群马" → 加载 community/worklog.md
```

当你说"聊写作"时，AI 就知道只加载写作域的记忆，不会把项目和社群的东西混进来。

### 一句话

**AI 的记忆要像图书馆，按需借阅，不是一次性搬回家。**

## 原则四：存档必须联动 (Bookmark-Worklog Linkage)

### 规则

> 每次保存会话进度（打书签），**必须先更新唯一进度源**，然后书签里只记一个轻量指针。

### 为什么

"会话书签"是个好东西——下次接着聊的时候，你能知道上次聊到哪了。但如果书签里把完整进度抄了一份，它就变成了进度的第二个副本，迟早和唯一进度源对不上。

我们发现过一个真实案例：书签是下午写的，工作日志是上午更新的，中间几个小时的进展只存在书签里，工作日志完全不知道。

### 怎么做

保存书签时，两步走：

```
第一步（必须先做）：更新工作日志（唯一进度源）
第二步（然后才做）：写一个轻量书签

书签内容：
  - 在聊什么（一句话）
  - 进度 → "详见工作日志"
  - 当前断点（下次从哪接着来）
  - 下一步（最多3条）
```

### 一句话

**书签是路牌，不是地图。它告诉你往哪看，不是把所有东西重抄一遍。**

## 原则五：定期瘦身 (Regular Pruning)

### 规则

> 记忆会自然膨胀，要定期清理过时的、重复的、已经不需要的信息。

### 为什么

就算遵守了前四条原则，记忆还是会慢慢变胖：

- 完成的任务还占着条目
- 临时的决策记录过期了还在
- 试验性的东西写进去了没删
- 同一件事换了说法记了两遍

膨胀的记忆不只浪费空间，更会让 AI 分心。**记忆里的噪音越多，AI 抓重点的能力越差。**

### 怎么做

定期做一次"记忆体检"：

```
检查清单：
□ 核心记忆超过容量上限了吗？（建议 <50%）
□ 有没有已完成的任务还在占位？
□ 有没有重复的信息？
□ 有没有只在特定场景用但放在了核心记忆的？
□ 工作日志里有没有过时的条目？

处理方法：
- 已完成 → 归档或删除
- 重复 → 保留一份，删其他
- 场景限定 → 搬到对应的域外挂里
- 过时 → 直接删
```

### 一句话

**记忆管理不是一次性工程，是持续的卫生习惯。**

---

## 五条原则的关系

```
原则二（极简） ← 什么该放进来
    ↓
原则三（暗号） ← 放不进来的怎么找到
    ↓
原则一（单一源）← 找到的信息以谁为准
    ↓
原则四（联动） ← 更新时怎么保持一致
    ↓
原则五（瘦身） ← 长期怎么不退化
```

它们形成一个闭环：从"放什么"到"怎么找"到"以谁为准"到"怎么更新"到"怎么维护"，覆盖了记忆管理的完整生命周期。
