# 工作日志轮转指南

> 当工作日志越来越长，AI 加载时"注意力"被稀释怎么办？
> 本指南提供一套轻量的轮转规范，让日志始终保持精简。

---

## 什么时候需要轮转？

```
⚠️ 触发信号：
  · 工作日志超过 80 行 或 5KB
  · AI 加载后明显"记不住"日志尾部的内容
  · 日志里超过一半的条目已标记"完成"

✅ 不需要轮转：
  · 日志在 50 行以内，读着不费劲
  · 大部分条目都是活跃的
```

## 轮转怎么做？

### 第一步：识别"冷条目"

冷条目 = 已完成 + 超过 7 天没有被引用。

在日志里找这样的条目：
```
✅ 已完成的任务描述（2025-04-01）    ← 冷了，可以轮转
🔄 正在进行的任务                    ← 热的，留着
📋 待做但近期要用的                   ← 留着
```

### 第二步：搬到归档文件

在同一目录下创建 `worklog-archive.md`：

```
📁 你的域目录/
├── worklog.md           ← 只留活跃条目
└── worklog-archive.md   ← 冷条目搬到这里
```

归档文件的格式很简单——按时间倒序排列，每条带日期：

```markdown
# 工作日志归档

## 2025-04 归档

- ✅ 完成了 XXX 功能（04-15）
- ✅ 修复了 YYY 问题（04-10）
- ✅ 重构了 ZZZ 模块（04-03）

## 2025-03 归档

- ✅ 初始化项目结构（03-28）
- ...
```

### 第三步：在日志里留个"指路牌"

轮转后，在工作日志顶部加一行提示：

```markdown
> 📦 历史记录见 worklog-archive.md（最近一次轮转：2025-04-15）
```

这样 AI 知道有归档可查，需要时会自己去读。

## 根目录文件的轮转

根目录（memory/）也会积累一次性的产出物。处理方式：

```
活跃参考文件  → 留在根目录（env-reference、trigger-table 等）
历史产出物    → 移到 archive/ 子目录
梦整理报告    → 移到 .dreams/ 子目录
```

**判断标准：** 这个文件下周还需要直接引用吗？
- 是 → 留着
- 否 → 归档

## 轮转频率

```
推荐：每月一次，或触发信号出现时
方式：告诉 AI "帮我轮转一下 XX 域的工作日志"
      AI 会识别冷条目，搬到归档，更新指路牌
```

## 注意事项

1. **归档不是删除** —— 冷条目只是搬家，随时能查
2. **不要轮转铁律/原则** —— 它们永远是"热"的
3. **书签（session-bookmarks）不需要轮转** —— 它们天生就是精简快照
4. **有疑问就别轮转** —— 宁可多留几条，也不要删错了找不回来

## 实战案例

### 案例：根目录清理（2025-04-15）

清理前：
```
memory/
├── env-reference.md             102行  5.1KB  ← 活跃参考
├── experience-opencode-feishu.md 104行  4.0KB  ← 活跃参考
├── experience-parsing.md         33行  1.3KB  ← 活跃参考
├── trigger-table.md              28行  2.4KB  ← 活跃参考
├── ai-daily-2026-04-07.md       113行 10.6KB  ← 历史产出
└── 2026-04-12-vertical-redesign.md 130行 5.6KB ← 历史产出
```

清理后：
```
memory/
├── env-reference.md             ← 留
├── experience-opencode-feishu.md ← 留
├── experience-parsing.md         ← 留
├── trigger-table.md              ← 留
└── archive/
    ├── ai-daily-2026-04-07.md       ← 归档
    └── 2026-04-12-vertical-redesign.md ← 归档
```

**效果：** 根目录从 6 个文件（28KB）瘦身到 4 个文件（12.8KB），减少 54%。历史产出物安全归档，需要时随时可查。
