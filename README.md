# 🧠 AI Memory Architecture

> **A battle-tested methodology for managing AI memory.**
> Works with ChatGPT, Claude, Cursor, Windsurf, Gemini, DeepSeek, Kimi — no coding required for the core method.
>
> 🌍 **English overview:** [README.en.md](README.en.md) · 🤝 [Contributing](CONTRIBUTING.md) · 🗺️ [Roadmap](ROADMAP.md)

**让 AI 真正记住你——更重要的是，让它别同时相信两份互相打架的“记忆”。**

> 📦 **项目核心是一套方法论 + 即用模板，并附带一个可选的本地结构检查器。**
> 方法论本身不需要编程、不绑定任何 AI 工具；会用 Python 的用户还可以运行 Memory Integrity Check（记忆完整性检查）自动发现结构问题。

> “AI 能记住很多东西，不代表它知道哪一份才是现在真正有效的。”

---

## 痛点

你是否经历过：

- 🔄 跟 AI 解释过的偏好，下次还要再说一遍
- 📝 上周让 AI 帮你做到一半的事，它完全不记得了
- 🗂️ 把笔记塞进 AI 的记忆里，越塞越乱，最后 AI 反而更糊涂
- 🤯 同时用 AI 做好几件事（写代码、写文档、做项目），记忆全混在一起
- ⚠️ 一个地方写“现在用方案 A”，另一个旧书签还写“继续方案 B”，AI 不知道该信谁
- 📌 会话书签本来只是记录“做到哪了”，时间久了却偷偷变成第二份项目进度

这不只是“AI 记不住”的问题。很多时候真正的问题是：**AI 已经记了太多，但这些记忆缺少权威关系、生命周期和一致性约束。**

---

## 这是什么

这是一套**不依赖任何特定 AI 工具**的记忆治理与上下文管理方法论。

它来自真实场景：一个非技术背景的用户，和 AI 助手在长期、多项目、高频协作中不断遇到“旧信息没删、进度多份、上下文串项目、暂停后恢复错版本”等问题，最后逐步形成一套多层结构。

**核心思想不只是“怎么存记忆”，而是“谁有资格代表当前事实”。**

比如：

- 一个项目只能有一个**权威进度源**；
- 会话书签只能是**指针**，不能偷偷复制一份项目状态；
- 核心记忆必须足够小，避免所有东西都永久塞进上下文；
- 过期引用、未解决矛盾、重复权威源应该被主动发现，而不是等 AI 猜。

## 跟 Mem0、Letta、Memory Bank 这些有什么不同？

AI 长期记忆已经是一个很大的开源领域。Mem0、Letta/MemGPT、LangMem、Basic Memory、Cline/Roo Memory Bank、Graphiti/Zep、MemoryWiki，以及很多 Markdown 跨 Agent 方案都已经做了大量工作。

**这个项目不声称自己发明了“AI 长期记忆”“Markdown 记忆库”“Git 保存上下文”或者“跨 Agent 交接”。这些都早已有成熟或正在快速发展的实现。**

我们的定位更窄：

> **存储系统回答“记忆放在哪里”；检索系统回答“这次该找哪段记忆”；AI Memory Architecture 主要回答“哪一份状态才是权威，以及这些记忆彼此有没有打架”。**

所以长期方向不是再造一个 Mem0，而是做一个轻量、可移植的 **Memory Governance（记忆治理）/ Structural Integrity（结构一致性）层**。

详细横向对比见：[Prior Art and Project Positioning →](docs/07-prior-art-and-positioning.md)

## 你的 AI 属于哪一档？

不同 AI 工具对记忆的支持程度不同。我们分成三档，**每一档都能用这套方法论**，只是操作方式不同：

| 档位 | 代表工具 | 记忆特点 | 你要做的 |
|------|---------|---------|---------|
| 🟢 **满血档** | Cursor / Windsurf / Claude Code / Trae / Hermes Agent | 能读写本地文件，模板直接用 | 复制模板到项目里，按指引配置 |
| 🟡 **半血档** | ChatGPT Memory / Claude Projects / Gemini Gems | 有内置记忆但控制有限 | 把核心记忆贴进设置，手动维护 |
| 🔴 **手动档** | Kimi / DeepSeek / 豆包 / 通义千问 / 任何纯对话 AI | 无持久记忆，每次对话从零开始 | 每次开聊时贴一段“记忆简历” |

> 💡 **不确定自己属于哪档？** 看 [快速开始](docs/03-quickstart.md)，里面有判断标准和每档的 1-2-3 步骤。

## 五条核心原则

| # | 原则 | 一句话解释 |
|---|------|-----------|
| 1 | **单一进度源** | 每件事的进度只在一个地方记录，其他地方只放指针 |
| 2 | **核心记忆极简** | 塞进 AI 脑子里的东西越少越好，放不下的扔外挂 |
| 3 | **暗号触发** | 说一个暗号，AI 自动切换到对应的记忆域 |
| 4 | **存档必须联动** | 保存进度快照时，必须先更新唯一进度源 |
| 5 | **定期瘦身** | 记忆会膨胀，要定期清理过时信息 |

## Memory Integrity Check V1（记忆完整性检查）

为了让这些原则不只停留在文字层面，仓库现在提供了一个**本地、确定性、不调用大模型**的小工具。

它可以检查：

- 同一个项目是不是出现了两个权威进度源；
- 同一个权威文件是不是被两个不同项目重复占用；
- Bookmark 是否指向不存在或错误的权威源；
- 同一个 Bookmark 是否重复登记；
- 老引用指向的文件是不是已经消失；
- 是否还有未解决或重复登记的矛盾；
- Core Memory 是否超过自己声明的大小上限；
- `./worklog.md` 与 `worklog.md` 这类路径别名是否其实指向同一个文件；
- 路径是否试图逃出项目目录；
- Manifest 是否出现了规范之外的未知字段。

运行：

```bash
python tools/memory_integrity_check.py path/to/memory-integrity.json
```

## 常见问题

**Q: 这跟 ChatGPT 自带的记忆功能有什么不同？**

ChatGPT Memory 解决的是“平台帮你持续记住一些信息”。这个项目更关心“你长期做项目时，哪些信息是核心、哪些是外挂、哪一份进度才算权威、旧状态有没有和新状态冲突”。二者可以同时使用，并不互斥。

**Q: 这是不是另一个 Mem0？**

不是。Mem0 这类项目重点是存储、提取和检索长期记忆。这里不打算再造一个记忆数据库，核心目标是提供**治理规则 + 可移植结构 + 一致性检查**。

**Q: 我只用一个 AI 做一件事，还需要这个吗？**

如果对话很短，不需要。如果长期协作、经历多次会话、不断做决定和更新进度，那么“哪份信息才是现在有效的”会逐渐变成真实问题。

**Q: 我完全不懂技术 / 不会编程，能用吗？**

能。方法论和模板都是纯文本。Python 检查器是可选增强，不是使用这套方法的前置条件。

**Q: 国产 AI（Kimi、DeepSeek、豆包）能用吗？**

能。它们可以走“手动档”：把核心记忆和当前项目状态浓缩成可复制的文本，在新会话开始时加载。
