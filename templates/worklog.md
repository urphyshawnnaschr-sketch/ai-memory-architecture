# 工作日志模板

> 每个项目/领域一份。这是该领域进度的**唯一权威来源**。
> 其他地方提到进度时，一律写"详见工作日志"。

---

## [项目/领域名称] 工作日志

## 基本信息

- **开始日期：** YYYY-MM-DD
- **当前状态：** 进行中 / 暂停 / 已完成
- **简介：** [一句话说明这是什么]

## 当前活跃

> 最近在做的事情。保持更新，完成后移到"已完成"。

- [ ] [任务描述] — [当前状态/进展]
- [ ] [任务描述] — [当前状态/进展]

## 待办

> 计划要做但还没开始的。

- [任务描述]
- [任务描述]

## 已完成

> 做完的事情。记录完成日期，供将来参考。

- [x] [任务描述] — YYYY-MM-DD 完成
- [x] [任务描述] — YYYY-MM-DD 完成

## 关键决策

> 做过的重要决定和原因。以后要回溯"当时为什么这么做"时看这里。

- **YYYY-MM-DD：** [决策内容] — 原因：[为什么]

## 经验教训

> 踩过的坑、学到的东西。

- [教训内容]

---

> **使用提示：**
> - 这是进度的唯一权威源，保持最新
> - 其他文件（书签、核心记忆、技能文件）提到进度时只写"详见本工作日志"
> - "已完成"部分可以定期归档，避免文件太长
> - 任务从"当前活跃"做完后，及时移到"已完成"

---

## 示例（填好的样子）

```markdown
## 科技专栏 工作日志

## 基本信息

- **开始日期：** 2025-03-01
- **当前状态：** 进行中
- **简介：** 每周一篇 AI 工具评测专栏

## 当前活跃

- [ ] Cursor vs Windsurf 对比稿 — 已写完初稿，等修改
- [ ] 配图方案确认 — 等美编回复

## 待办

- GPT-5 发布后的评测稿
- AI 编程工具年度盘点

## 已完成

- [x] Claude Code 深度评测 — 2025-04-01 完成
- [x] Suno v4 音乐生成体验 — 2025-03-20 完成

## 关键决策

- **2025-03-15：** 频率从周更改为双周更 — 原因：质量比数量重要

## 经验教训

- AI 工具评测要用同一个任务做横评，不要各测各的，读者没法比较
```
